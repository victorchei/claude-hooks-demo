# claude-hooks-demo — режим живого показу

Це навчальне демо хуків Claude Code. Хук — це автоматична дія, яка
спрацьовує сама на певну подію (запис файлу, запуск команди, старт сесії).
Аудиторія бачить термінал наживо, тож кожна відповідь має **показувати роботу
хука**, а не просто повідомляти результат.

Відповідай українською, коротко, **простими словами**: демо читатимуть і
запускатимуть не лише розробники. Жодного жаргону без пояснення в дужках;
слова «Pre/PostToolUse» супроводжуй фразою «до дії» / «після дії».

## Старт сесії: залежності

Для хуків потрібен лише **Node.js 18+** (однаково працює на macOS, Windows,
Linux). Решту (`git`, за бажанням `gh`) SessionStart-хук ставить сам:
на старті він друкує `✓ Node … + усі залежності вже встановлено` або
`⚠ Бракувало: … — запущено install.mjs`.

Якщо в контексті є рядок `NODE_MISSING` або `node --version` дає помилку —
Node немає, і хуки не працюють. Тоді **до будь-якого демо**:

1. Поясни одним реченням: без Node не спрацює жоден із шести хуків
   (це «двигун», на якому вони написані; ставиться один раз).
2. Визнач ОС (`uname -s` у bash або `$env:OS` у PowerShell) і запропонуй
   команду: macOS — `brew install node` (без Homebrew — https://nodejs.org);
   Windows — `winget install OpenJS.NodeJS.LTS`; Debian/Ubuntu —
   `sudo apt install nodejs npm`; інакше — https://nodejs.org.
3. Спитай дозволу і виконай. Після встановлення попроси **перезапустити
   `claude`** з кореня репо — далі SessionStart-хук доставить решту сам.
4. Якщо користувач відмовився або потрібен пароль/адмін-права — дай команду
   для ручного запуску і зупинись; демо без Node не починай.

Якщо проєкт не git-репозиторій (архів замість `git clone`) — демо 3 неможливе:
поясни це й запропонуй `git init -b main` та перший коміт лише за згодою.

## Виконання

- Повний сценарій — команда `/demo` ([.claude/commands/demo.md](.claude/commands/demo.md)).
  Користувач може й просто просити кроки з README.
- Змінюй файли **лише інструментами Edit/Write**, а не через Bash
  (`echo >`, `sed`, `mv`, `cp`): хуки файлів спрацьовують саме на них.
- Команди для терміналу — сумісні з macOS, Linux і Windows.
- Виконуй прохання дослівно і **викликай інструмент**, навіть якщо
  очікуєш блокування: хук має спрацювати наживо. Не відмовляйся наперед.
- Заблоковано хуком — **не обходь**: жодного запису через `Bash`,
  жодного `--no-verify`, жодного перемикання гілки заради коміту.
- Не форматуй код сам і не запускай prettier/black вручну — це робить хук.
- Нічого не комітити, не пушити й не створювати PR без прямого прохання
  в цьому демо-кроці.

## Формат відповіді після кожного кроку з хуком

1. **Що зробив** — одне речення.
2. **Рядок хука** — процитуй дослівно з виводу (`🎨 …`, `🔒 …`, `🌿 …`,
   `📣 …`, `🔔 …`) у блоці коду. Якщо рядка немає — прямо скажи, що хук
   не спрацював, нічого не вигадуй.
3. **Що це показує** — одне речення: яка подія і чому хук зробив саме це.
4. **Доказ**, коли доречно: після демо 1 — `git diff src/app.js`; після
   блокування — що файл/коміт не змінився (перегляд папки, `git log --oneline -1`).

Після блокування: назви хук, причину й правильний шлях (feature-гілка +
Pull Request). Обхід не пропонуй.
